## خطة إصلاح مشروع OKR قبل مناقشة اللجنة

**قاعدة عامة:** لا تظهر عبارة "الطور" بأي صيغة في واجهة المستخدم نهائياً.

### 1. نصوص الأطوار الظاهرة (إزالتها كلياً)
- **التذييل** `src/components/layout/app-shell.tsx`: يصبح حرفياً: **"نظام إدارة الأهداف المؤسسية OKR"** — بدون "وفق منهجية" وبدون أي ذكر للأطوار.
- **الصفحة الرئيسية** `src/app/(app)/app/page.tsx`: عنوان القسم يصبح "إمكانيات النظام المتاحة" مع تحديث القائمة لتشمل كل الميزات الفعلية (الأهداف، الاعتمادات، تحديثات الإنجاز، التنبيهات، التقارير، لوحة المعلومات، البحث) بدل قائمة الطور الثاني القديمة، وحذف فرع شارة "قريباً" غير المستخدم.
- **الترويسة** `src/components/layout/app-header.tsx`: أيقونة البحث تصبح رابطاً فعلياً إلى `/app/search` وتُحذف تلميحة "البحث (قريباً)".
- **حذف مكوّن `upcoming-feature.tsx`** (كود ميت غير مستخدم) مع أي نصوص "قريباً — الطور القادم" متبقية.
- مسح شامل لأي بقية "الطور/Phase" في نصوص الواجهة (تبقى فقط في تعليقات الكود الداخلية وأسماء ملفات الطور، فهي لا تظهر للمستخدم).

### 2. صفحة تفاصيل الدورة — ربطها بالبيانات الحقيقية
`src/app/(app)/app/cycles/[id]/page.tsx`:
- جلب الأهداف التابعة للدورة من `usePhase3Store` (فلترة بـ cycleId) وعرضها بقائمة حقيقية بدل الرسالة الثابتة "ستُضاف في الطور الثالث"، مع حالة فارغة صادقة فقط إن كانت الدورة بلا أهداف فعلاً.
- حساب "تقدّم الدورة" فعلياً من حسابات الطور الرابع: عدد الأهداف، متوسط الإنجاز، عدد الأهداف المكتملة — بدل القيم "—".

### 3. المصادقة — إصلاح فعلي (اختيارك سابقاً)
- **مخزن بيانات اعتماد جديد** `src/lib/auth/credentials-store.ts` (zustand persist) يربط userId بكلمة مرور، يُهيّأ افتراضياً بـ Demo@2026 لكل الحسابات.
- **`loginWithCredentials`** يتحقق من مستخدمي المخزن المؤسسي (وليس المصفوفة الثابتة) + كلمة المرور من المخزن الجديد + حالة الحساب من المخزن — فيصبح تعطيل/تفعيل الحسابات حقيقياً والمستخدمون الجدد يدخلون فوراً بكلمة المرور الافتراضية.
- **`resetPassword`** يحفظ كلمة المرور فعلياً؛ صفحة `/reset-password` تطلب "اسم المستخدم أو البريد" عند عدم وجود جلسة، وتغيّر كلمة مرور المستخدم الحالي مباشرة عند وجود جلسة (تغيير كلمة المرور من الملف الشخصي).
- **نصوص صادقة**: تعديل رسالة "ستصلك تعليمات خلال دقائق" (لا بريد فعلي في النموذج) إلى صياغة مباشرة تنقل للخطوة التالية، فتصبح رسائل النجاح صحيحة بعد الحفظ الفعلي.

### 4. تنظيف المستودع
- حذف: `mini-services/`، `examples/`، `.zscripts/`، `tests/`، `download/`، `Caddyfile`، `project-v2.zip`، `scripts/gen-upcoming-pages.mjs`.
- الإبقاء على `upload/` (لصقاتك ووثائقك الخاصة) مع التوصية بنقلها خارج المشروع لاحقاً.
- `package.json`: الاسم يصبح `okr-management-system` وحذف اعتمادية `z-ai-web-dev-sdk` غير المستخدمة.
- `src/app/api/route.ts`: تحويله إلى health check بسيط بدل "Hello, world!".
- إضافة `README.md` عربي: وصف النظام، التقنيات، التشغيل، حسابات الدخول.
- التأكد من تجاهل `db/*.db` و`*.zip` في `.gitignore`.

### 5. التحقق النهائي
- `npm run lint` + `npm run build` حتى البناء الناجح.
- تشغيل خادم التطوير وفحص سيناريو اللجنة كاملاً في المتصفح: تسجيل الدخول، تعطيل حساب ثم محاولة دخوله، إنشاء مستخدم ودخوله، تغيير كلمة المرور وتجربتها، الدورة مع أهدافها ومؤشراتها، البحث من الترويسة، والصفحة الرئيسية والتذييل الجديد — مع إصلاح أي ملاحظة تظهر.
